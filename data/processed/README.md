# Подготовленные временные ряды

Все файлы пересоздаются из оригинального XLSX при запуске `analysis.ipynb`.
Товар: `20728 — LUNCH BAG CARS BLUE`. Единица измерения исходных сумм — единица SKU.

`sales_daily.csv` содержит 374 даты 2010-12-01–2011-12-09:

| Поле | Смысл |
| --- | --- |
| `date` | Начало календарного дня, локальная дата регистрации источника |
| `store_rows` | Все строки магазина после удаления точных дублей, до отбора положительных продаж |
| `units_recorded` | Сумма положительных Quantity по SKU, при положительной цене и счёте без C |
| `credit_units` | Модуль суммы отрицательных Quantity по кредитовым счетам C с положительной ценой |
| `net_recorded` | `units_recorded - credit_units`; может быть отрицательным |
| `store_observed` | Есть хотя бы одна строка магазина за день |
| `units_store_observed` | Объём зарегистрированных продаж, но NaN при отсутствии строк всего магазина |
| `is_saturday` | Суббота; в этой выгрузке все такие дни без записей |
| `silent_non_saturday` | Нет строк магазина, день не суббота; отдельно используется в чувствительности |
| `boundary_day` | Первая или последняя дата выгрузки; из основных тестов исключена |

Отсутствие продаж в активном магазине не доказывает отсутствие спроса: нет данных о запасах.
Отсутствие записей магазина также не доказывает сбой или закрытие. В основной метрике
ноль — объём записей данной выгрузки, а не восстановленное значение неизвестного спроса.

`sales_weekly.csv` и `sales_monthly.csv` содержат календарные суммы. `period_start`
и `start` — начало интервала, `end_exclusive` — исключённая правая граница.
Неделя начинается в понедельник; месяцы календарные. `days_in_extract` — число дат внутри
выгрузки, `calendar_days` — полная длина интервала, `store_days` — дни с записями магазина,
`uncertain_days` — пустые дни кроме суббот, `boundary_days` — пограничные даты.
`complete` означает полный календарный интервал без пограничных дат; он **не является
доказательством отсутствия внутренних пропусков источника**. `units_per_observed_day`
делит сумму на доступные календарные даты, включая даты без строк, а не на активные дни магазина.

`transformed_daily.csv` относится к основному интервалу 2010-12-02–2011-12-08.
Колонки: log1p продаж, первая разность log1p и разность с лагом 7.
NaN в начале разностных столбцов — ожидаемая потеря одного/семи начальных наблюдений,
а не пропуск исходных данных. Эти NaN не использовались в тестах стационарности.
